## V. Layout Principles

### Page Structure

- **Header area**: 左侧序号与章节眉题引导进入；主标题以结论句呈现，右侧以橙色状态标签明确“待核验，不是现状结论”。
- **Content area**: 三端从左到右形成并行但不等权的诊断路径。每端由“材料提出的诉求”向右跨越箭头进入“本地待测问题”，阅读路径清楚地表现“诉求不等于差距事实”。
- **Footer area**: 一条横向核验输出链将三端共用的事实底座收束为事项清单、流程图、系统接口清单和业务基线；附注界定其为建议动作而非既有台账。

## IX. Content Outline

### Part 1: 现状与差距核验

#### Slide 05 - 围绕群众、窗口与管理三端，形成待核实的能力差距清单

- **Audience move**: 从“规划可列出哪些功能”转向“先以哪三端问题和哪些基础台账验证真实缺口”。
- **Layout**: 顶部给出结论与事实边界；主体为三条纵向并行的诊断路径，每条均以左侧“原始材料中的服务诉求”经箭头指向右侧“待测问题”，不把两者混写为现状。底部以一条有序输出链连接三端，为下一步核验提供共同收口。
- **Title**: 三端体验诉求已经明确，但“真实差距”仍需逐项核验
- **Core message**: 原始材料说明了群众、窗口与管理的服务诉求，但没有给出五寨县本地业务量、时长、满意度、系统接口或运行现状基线；规划范围应以核验结果排序。
- **Content**:
  - 页面事实边界：标识“以下均为待核验项，不是现状判断”。
  - 群众端：原始材料提出找窗口与流程、填报材料、排队等待和线下跑动等诉求；待测问题为窗口与流程指引是否清晰、材料填报摩擦和排队/跨点位办理体验如何。
  - 窗口端：原始材料提出业务知识学习压力与总体工作负荷诉求；待测问题为知识查询、材料核验、受理派单、回访与质检的重复工作量及受理链路如何。
  - 管理端：原始材料提出大厅运行监控、数据汇聚与辅助决策诉求；待测问题为人流、窗口效能、服务质量、数据汇聚和突发响应能力如何。
  - 建议核验输出：事项清单 → 流程图 → 系统接口清单 → 业务量 / 时长 / 满意度基线。
  - 事实说明：建议输出是规划落地的核验动作；原始材料未提供上述本地基线或既有台账。
  - Source reference: 原始规划材料《二、需求分析》《三、建设目标》；本页不使用材料中的拟配设备、预期比例或外地案例数据作为五寨县事实。
