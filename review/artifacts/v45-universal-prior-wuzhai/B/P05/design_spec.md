## III. Visual Theme

### Theme Style

- **Mode**: pyramid
- **Visual style**: data-journalism
- **Theme**: 决策核验页；用一条“问题 → 核验输出 → 建设排序”的证据链统领三端，而非把三端做成并列功能清单。

## IX. Content Outline

### Part 1: 现状核验与建设范围

#### Slide 05 - 围绕群众、窗口与管理三端，形成待核实的能力差距清单

- **Audience move**: 从“直接讨论要建什么” → “先用三端问题与统一证据包验证真实短板，再决定建设排序”。
- **Layout**: 结论式页头下方为三列端侧诊断带：群众端、窗口端、管理端依次呈现，每列的橙色“待测”动作与蓝色“核验对象”彼此成对；三列共同汇入底部横向“最小核验输出”证据带，再由一条清晰箭头指向“形成建设范围与试点排序”。不使用现状进度、比例或性能数值。
- **Title**: 先核验三端真实问题，才能确定建设范围与试点排序
- **Core message**: 原始材料已识别三类服务诉求，但尚未证明其在五寨县的基线、成因和优先级；本页把诉求转换成可验证的问题清单。
- **Content**:
  - 顶部边界句：原始材料未提供平均等待时长、跑动次数、人员负荷、满意度或数据接入现状；以下均为“待核实”项。
  - 群众端｜体验摩擦待测：找窗口与流程指引、材料填报、排队等待、跨层级/跨点位办事体验。核验对象：事项清单、流程图、业务量/时长/满意度基线。
  - 窗口端｜重复工作待测：知识查询、材料核验、受理派单、回访与质检的重复工作量。核验对象：知识库与规则现状、窗口作业观察、系统接口清单。
  - 管理端｜运行感知待测：大厅人流、窗口效能、服务质量、数据汇聚与突发响应能力。核验对象：运行数据口径、数据链路、场地与网络条件。
  - 汇聚输出：事项清单＋流程图＋系统接口清单＋业务量/时长/满意度基线。
  - 行动落点：将已核实的“问题—成因—影响”用于确定建设范围和试点优先级。
- **Visualization**: 三个同层的端侧诊断单元通过“待测问题 → 核验对象”纵向关系连接到底部统一证据带；统一证据带再以单向箭头连接行动落点。三端是并列维度，底部输出是共同依赖，不能被阅读为现状已达成。
- **Native shape suggestion**: 用圆角矩形承载三端诊断单元，用直线连接符表达“端侧问题 → 共同核验输出 → 排序决策”的单向依赖。
