# Plan Semantic → PPT Master Native Design Intent

`presentation_plan.md` 是 Direct Plan Profile 与 PPT Master 的主要业务接口。专业 Prompt 只产生演示语义，不包含任何下游实现知识；本文件仅供 Master 侧集成时理解这些语义。

## Strategist 的翻译责任

- **页面任务**：判断本页承担的沟通动作，例如建立认识、形成判断、证明成果、解释机制、暴露问题、比较差异、形成决策或推动行动；不直接指定布局。
- **核心观点**：确定页面第一视觉焦点和最重要结论，让视觉权重服务这一判断，而非把所有内容等权处理。
- **内容关系**：作为页面空间关系的重要输入。存在并列、递进、因果、层级、流程、依赖、汇聚、系统协同或对比等真实关系时，优先考虑让主空间结构直接表达它。
- **信息主次**：决定尺度、视觉重量、信息层级、留白和证据退后程度。核心、支撑和补充信息不应默认使用同等视觉权重。
- **表达意图**：帮助判断本页是强化重点、舒展停顿、正常推进、集中承载还是完成过渡，并据此形成合适的页面节奏与构图。
- **可用素材**：识别具有事实和证据价值的照片、截图、数据、流程或案例；是否使用、如何处理和如何融合由 Master 自主判断。

## 原则

当页面存在明确的层级、流程、递进、依赖、汇聚、系统协同、因果或对比等真实关系时，Strategist 应优先让主空间结构表达这种关系，而不是默认把每项内容装入同等大小的圆角矩形。

当页面主要承担事实核验、指标审阅、明细对照或数据承载任务时，表格、模块或卡片仍然可以是合理选择。页面设计不以避免卡片为目标，而以准确表达内容关系、信息主次和沟通任务为目标。

本协议不把语义关系映射为固定图表、模板、坐标、字体、颜色或几何。Master 结合模板、内容量、视觉风格、整套节奏和当前原生能力自行决定实现。

## 边界

Router 不输出具体版式、图形、图表名称、Native Shape 参数、SVG 参数或 Executor 几何。PPT Master 结合原始材料、用户要求、模板/参考和 `presentation_plan.md`，按当前版本原生流程完成设计与生产。

Router → Master 只交接类型化路径、用户明确要求和短 activation，不传 Router 内部 Prompt 内容、Profile 全文、Lens、Kernel、scoring 或调试历史。
